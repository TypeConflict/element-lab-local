# 元素實驗室

一個可在自己電腦運行的元素合成與抽象概念萃取遊戲。經典模式不需要帳號或 API 金鑰；接入自己的模型後可自由探索。

## 快速開始

1. 安裝 Node.js 22.13 或以上版本。
2. 從 GitHub 下載專案 ZIP 並解壓，或 clone 本專案。
3. 在專案資料夾開啟終端機，執行 `npm start`。
4. 用瀏覽器開啟 [http://127.0.0.1:4175](http://127.0.0.1:4175)。

專案沒有第三方 npm 依賴，不需要先執行 `npm install`。首次啟動會自動建立自己的資料庫。需要 LLM 時才複製 `.env.example` 為 `.env` 並設定模型。


繁體中文、深色響應式元素合成遊戲。頂部雙材料槽、彩色膠囊元素、收藏、分類篩選、名稱排序、元素搜尋，以及 SQLite 本機存檔。四個起始元素、60+ 內建配方，支援拖放與點選合成。兩個元素不分順序，相同元素也可以合成。

## 全櫃搜尋

工具列只搜尋所有已發現造物的名稱（不搜尋 reason 介紹），不受分類與收藏篩選限制。多個關鍵字以空白分隔，結果須同時符合所有詞語；英文字母不分大小寫，全半形視為相同。搜尋結果保留最新／名稱排序，也可直接選取或拖曳到材料槽。按 × 或 Esc 清空後恢復原本的篩選；點分類則結束搜尋並切換分類。

## 畫面與排序

元素預設按最新發現優先排列，包含合成與萃取結果；重新開啟遊戲後保留同樣順序。「最新／名稱」按鈕可切換名稱排序。重複取得已有元素不會改變它首次發現的順序。桌面版採 1120px 置中版面，底部操作列與遊戲同寬。

## 造物字典與合成操作

工具列「📖 字典」可搜尋已合成過的造物。點選條目可查看 reason 介紹，以及曾成功使用的兩種材料；同一造物的多種配方會分別列出，材料交換順序不會重複列入。字典查詢完整 SQLite 紀錄，不受最近 200 筆的顯示限制。舊資料缺少來源時會明確標示，不會預先揭露尚未合成的配方。

每次合成結束（包含無配方或服務失敗），兩個材料槽會自動清空，結果或錯誤說明以置中小彈窗呈現，點畫面任意位置（含彈窗內外）或按 Esc 即可關閉。

## 萃取抽象概念

工作台固定保留兩個材料槽。只放入一個造物時，底部固定操作列只開放「◈ 萃取」；放入兩個材料時只開放「＋ 合成」。零個材料或處理中，兩個按鈕皆停用。不論捲動到哪裡都能使用底部操作列。例如火 → 熱情、水 → 流動、森林 → 共生。萃取不消耗來源，每次得到一個概念，完成後自動清空材料槽。新概念進入元素清單及「抽象概念」分類，可用於後續合成；經典合成仍受內建配方限制，LLM 合成可探索任意組合。

經典模式有 28 個來源的萃取配方，未收錄的來源會提示沒有配方。LLM 模式沿用 `.env` 的模型設定，專門要求模型提取象徵、價值、情緒或關係，不拆出實體零件。語意品質取決於模型；會拒絕直接回傳來源名稱的結果。同一來源會重用保存的結果，不會每次隨機產生。

資料庫會自動相容升級：舊操作記為合成，新萃取保存單一來源和 `kind: extract`；字典會顯示「萃取自」。歷史存檔和收藏保持不變。

自訂遠端服務可在「模型設定」另填萃取服務網址；留白使用本機 `/api/extract`。此服務接收 `{"source":"火"}`，回傳 `{"name":"熱情","emoji":"❤️‍🔥","reason":"火的熾熱象徵熱情。"}`。不會假設舊合成服務也支援萃取。

## 本機遊玩

使用 Node.js 22.13+（需要內建 node:sqlite；需要支援 node:sqlite），不需要安裝套件：

```sh
npm start
```

開啟 http://127.0.0.1:4175 。預設經典模式，不需 API 金鑰。

## 接入 LLM

1. 將 `.env.example` 複製為 `.env`。
2. 填入 `LLM_URL`、`LLM_MODEL`，需要時設定 `LLM_API_KEY`。
3. `LLM_PROTOCOL=ollama` 使用 Ollama 原生 Chat API；`compatible` 使用支援 `messages`、`response_format: {type: "json_object"}` 的 Chat Completions 相容服務。
4. 啟動 `npm start`；遊戲右上「模型設定」切換 LLM，服務網址留白即使用同來源 `/api/combine`。

Ollama 協定依官方文件：https://docs.ollama.com/api/chat 。需先自行安裝模型；本專案不會下載模型或提供金鑰。自動化測試使用模擬模型回應，不需要金鑰，也不會產生模型費用。

## 本機資料庫與備份

資料庫位於 `data/element-lab.sqlite`，以專案路徑為基準，與瀏覽器儲存空間分開。元素、收藏、配方、合成紀錄與設定會保存；重新整理、重啟伺服器或換瀏覽器後仍會讀取同一份進度。畫面底部顯示寫入狀態；失敗時可重試。所有使用此本機伺服器的分頁共用同一份資料庫。

此分享版不附任何玩家進度或設定，第一次啟動只會建立水、火、風、土四個起始元素。瀏覽器備援使用獨立的 `element-lab-share-v1` 名稱，只會合併此分享版的備援資料，不會匯入私人版的 `element-lab-v1`。預設使用 4175 埠，方便與其他本機版本分開運行。你之後的進度仍會自動保存。

**備份方式：** 先停止遊戲伺服器，再複製整個 `data/` 資料夾；還原時也先停止伺服器，再放回 `data/`。使用 WAL 模式時，執行中不可只複製單一 `.sqlite` 檔案。資料庫不會加入 Git，也不會上傳。

可用 `DATABASE_PATH` 指定其他 SQLite 路徑。請保留資料庫檔案；清除瀏覽器資料不會刪除 SQLite 進度。本機頁面需透過 `npm start` 開啟，不能直接雙擊 HTML。

## 後端

`server.mjs` 監聽本機 loopback；本版以本機遊玩為主，不部署網站。要連外部 LLM 合成服務，可在設定填入完整 HTTPS 端點。本機 `.env` 存放模型服務設定與金鑰。請勿把金鑰放在前端。

合成服務契約：

```http
POST /api/combine
Content-Type: application/json

{"a":"水","b":"火"}
```

```json
{"name":"蒸汽","emoji":"♨️","reason":"水遇熱化為蒸汽。"}
```

未知經典配方不會生成虛假的結果。LLM 結果依服務與無序元素組合快取；新發現僅代表此本機資料庫首次發現，不代表全球首次。畫面顯示最近 200 筆紀錄，完整紀錄保留在 SQLite。

## 驗證

`npm test` 驗證配方可達性、交換順序、LLM 回應契約、資料庫重啟復原、舊進度合併與錯誤處理。瀏覽器支援 `document.modelContext` 時會額外註冊 `list_elements`、`combine_elements` 及 `extract_concept`；不支援時不影響遊戲。
